# Learning architecture and acceptance

This document describes the current frontend. The [UI/UX backlog](ui-ux-audit.md) distinguishes remaining requirements from implemented behavior. Contributor rules live in [AGENTS.md](../AGENTS.md); types and algorithms are authoritative in source rather than duplicated here.

## Routes and coexistence

- Mobile navigation uses Home, Progress, Forum, and More. Home groups Lessons, Practice, and Morse table; Forum includes its threads; More groups About, account pages, and preferences, with shortcuts to training. The shared layout keeps desktop matching separate and hides navigation during guided sessions and the bottom bar during text entry. Training pages omit the duplicate section tabs.
- [Home](../src/routes/+page.svelte) keeps the public landing page for guests without saved training activity. Signed-in users and guests with lifetime saved answers or completed training history see Lessons and Practice first, a secondary Morse table link, then a recent activity summary and full Progress link. The lesson title includes its introduced characters and opens the recommended session directly. Unfinished work routes through the explicit restart/dismissal flow on Lessons; course completion, loading, and failure also retain the overview link. Training links stay available while data loads or fails. Empty lesson starts and settings alone do not qualify. Browser initialization, storage failure/retry, and account changes are handled separately; cached history from other owners is never displayed.
- [Lessons](../src/routes/morse/learn/+page.svelte) uses the owner's lifetime attempt count to distinguish newcomers, then derives recommendations from recent synchronized/local history through [course guidance](../src/lib/training/v2/course-guidance.ts). It stops at the first unstable lesson and requires stable evidence across the whole curriculum before showing completion. Per-character remaining checks show current values and targets from the [mastery policy](../src/lib/training/v2/types.ts); lesson bounds come from the curriculum. Only the latest local unfinished session can offer a restart; restart and dismissal persist abandonment while retaining saved answers and unknown interruption end times. Exact prompt restoration is not implemented.
- [CoursePath](../src/lib/components/learning/CoursePath.svelte) shows the previous/current/two upcoming lessons, with earlier/later rows in native disclosures. The current row stays outside disclosures. The [curriculum](../src/lib/training/sequence.ts) contains 39 lessons introducing 40 characters.
- [Guided session](../src/routes/morse/learn/session/+page.svelte) creates browser resources and a [reactive controller](../src/lib/training/v2/session-controller.svelte.ts). The controller coordinates prompt playback, scoring, persistence, and interruption handling using the [pure guided state machine](../src/lib/training/v2/guided-session.ts). Initialization has a retry state and ignores stale asynchronous work; route changes and disposal release owned resources. Introductions require completed audio before Continue becomes available; Listen changes to Continue in place and replay becomes secondary. Interrupted or failed playback remains retryable without creating recognition evidence. Warm-up answers are recorded as unmeasured regardless of correctness. Unscored warm-ups use large choices, followed by inline sound comparison after mistakes; replaying either sound leaves the saved answer and mastery evidence unchanged. Typed recall shares these sound controls and feedback, announces the start of scored practice, and keeps partial group answers through replay, pause, and cancelled exit. Plain Space replays from the answer field; complete answers submit automatically after composition ends. Scored comparison choices share this layout while keeping their scored status separate from the input method. Results show correct/scored counts, response time, and replay scope, with unmeasured states when evidence is absent. Guidance and the next/repeat/finish action follow the existing progression reason; course completion makes Finish primary. Device-save status and retry appear once within completed results, with account-sync attention separate. Completed sessions leave without an unfinished-lesson confirmation. Result metrics and session controls reflow with enlarged text.
- [Practice](../src/routes/morse/practice/+page.svelte) opens continuous copy directly, retaining the separate [passage state machine](../src/lib/training/session.ts), [attempt snapshots](../src/lib/practice/copy-attempt.ts), and shared [playback controller](../src/lib/practice/playback.ts). Checked passages save device history with their score, settings, and first playback/completion times. Failed writes retain the same record for retry. Free practice does not unlock guided progression or create recognition evidence.
- [Morse table](../src/routes/morse/+page.svelte) opens unscored character familiarization with the full curriculum available. One character grid controls the selected character and sound replay. It may show Morse notation because it is a reference mode. Existing Practice links with `?mode=familiarize` redirect here; `?mode=copy` continues to open copying.
- [Progress](../src/routes/morse/progress/+page.svelte) reads the full indexed seven-day session range, recent guided attempts, and recent session history, then delegates metrics and diagnostics to the [pure summary reducer](../src/lib/training/v2/progress-summary.ts). It shows activity, actionable diagnostics when present, character mastery, then recent sessions. History uses responsive rows with labeled status icons, separate character/effective speeds, and accuracy bars beside measured percentages; guided titles include introduced characters. Guided lessons and practice both contribute activity counts and time, while recognition accuracy and mastery use guided attempts. Recorded session time comes from valid timestamps; absent measured evidence stays unmeasured. Loading, empty activity, and storage failure/retry are distinct. Character buttons expose their status and measurements on hover, focus, or tap. The diagnostics action opens free practice without claiming a targeted session.
- [Profile](../src/routes/profile/+page.svelte) groups account identity, an interactive activity calendar, and current-year training habits. Calendar days show localized dates and completed-session counts on hover, focus, or tap; arrow keys navigate days through one Tab stop. [Habit calculations](../src/lib/profile-heatmap.ts) count distinct completed-session UTC days, consecutive-day streaks, and the most active weekday from available history. Settings is linked beside the page title. Guests see device-local activity context without account membership claims. Training performance, session history, and playback settings remain on their owning pages.
- Secondary Morse table, practice, course, and history explanations use [info tips](../src/lib/components/InfoTip.svelte), available on hover, keyboard focus, or tap. Training instructions and warnings remain visible.

Lessons and Progress close connections on failure or unmount and ignore late initialization results. Progress closes its read connection after loading. Recommendation, session, practice, result, and progress copy use the five [message catalogs](../messages/); the shared layout owns their outer page padding.

## Domain, audio, and persistence

[Prompt types](../src/lib/training/v2/types.ts), [lesson building](../src/lib/training/v2/lesson-builder.ts), [attempt scoring](../src/lib/training/v2/attempt.ts), [mastery](../src/lib/training/v2/mastery.ts), and [progression](../src/lib/training/v2/progression.ts) are pure TypeScript. The controller is the Svelte orchestration exception; presentation components emit intent rather than owning domain decisions.

`reduceCharacterMasteries` indexes a history once for multi-character analysis and shares an evaluation time. Progress and progression use it. Lessons deliberately uses the single-character reducer to preserve its early exit; eagerly computing every character can increase work for that route.

[Timing](../src/lib/training/timing.ts) produces plans in seconds; the [audio engine](../src/lib/audio/engine.ts) schedules them and creates Web Audio resources on playback. Attempt latency is stored in integer milliseconds. Audio completion and replay counts feed assessed recognition; inspection/repair must not create duplicate scored attempts.

[IndexedDB](../src/lib/data/training-db.ts) and the [attempt](../src/lib/data/attempt-repository.ts)/[session](../src/lib/data/session-repository.ts) repositories store both modes under compound owner keys. The [versioned schema](../src/lib/data/training-schema.ts) preserves original stores as archives and copies their unowned records into `unclaimed`; account partitions use the immutable JWT subject, never username. Transaction success waits for commit; late aborts reject. Each attempt, session count, and outbox entry commit together. Terminal metadata derives local guided accuracy, freezes the entire attempt manifest, and queues atomically; practice queues only its passage summary. The [pending persistence manager](../src/lib/pending-training-persistence.ts) retains failed guided write queues under their original owner across route/account changes, retries, and closes resources after success. Browser unload guards still apply: a write that cannot reach browser storage cannot survive a forced process exit. The [navigation guard](../src/routes/morse/learn/session/navigation.ts) permits explicit unsaved discard and retains cancelled Back/Forward destinations.

[Synchronization](../src/lib/training-sync.svelte.ts) starts in the root layout and runs on login, local saves, navigation, reconnect, focus, and visible return. It uses captured owners, authentication cancellation, per-account Web Locks when available, and cross-tab notifications. The [engine](../src/lib/training-sync-engine.ts) uploads strict-schema-2 guided attempts before schema-1 terminal sessions, preserves frozen work on transient failures, honors retry delays, and retains permanent rejections without blocking unrelated sessions. The [wire adapter](../src/lib/training-wire.ts) validates downloads before storage. The [sync repository](../src/lib/data/training-sync-repository.ts) commits a download page and checkpoint together, compares the expected cursor to reject stale concurrent pages, and never re-enqueues downloads or overwrites pending local payloads. Epoch reset restarts downloads while retaining pending work. No API response is cached by the service worker.

Progress offers explicit device-history import into the current account. The durable installation/kind/record journal prevents a second account from claiming the same source; identical already-downloaded records can be adopted without duplication. [Legacy localStorage migration](../src/lib/data/legacy-migration.ts) retains old settings and ambiguous progress queues; the old uploader is no longer initialized and ambiguous entries are never automatically resubmitted. Nullable legacy history preserves unknown mode, settings, timing, and counts. Profile reads unified sessions once instead of adding legacy progress a second time, and optional remote account metadata cannot hide cached history offline. Completion determines activity dates when known; UTC heatmap days and actual account join metadata remain distinct.

The shared [status component](../src/lib/components/TrainingSyncStatus.svelte) hides routine status on learning pages and links pending uploads or synchronization errors to Settings → Sync & storage, also linked from mobile More. Settings keeps the expanded status, manual synchronization, explicit device-history import, and cache controls available independently of account-settings loading. Background synchronization remains in the root layout. Active guided metadata is not labeled synchronized until terminal metadata and evidence acknowledge. Account switches stop training audio, clear rendered history, and retain original-owner writes. Cache clearing refuses pending work and active account sessions, retains unclaimed history/import assignments, and notifies accounts to redownload. The [approved API specification](../../backend/docs/training-history-v1-spec.md) owns server contracts and remaining V2 retirement gates.

## UI acceptance requirements

These are requirements for changes, not a claim that every existing flow passes them:

- Preserve the [shared design tokens](../src/app.css), five-locale messages, semantic feedback, theme support, and reduced motion. The layout owns page padding and mobile navigation clearance.
- During assessed recall, reveal no Morse notation or visual decoding cues. Inspection and post-answer repair must remain clearly distinct from scoring.
- Provide one clear primary action, stable answer positions, 44px minimum/48px preferred targets, 8px target spacing, visible focus, and text/icons with success/error feedback.
- Space plays/replays and Enter submits/continues only in the appropriate phase. The guided route owns Enter continuation for introductions, feedback, and sound comparison through the [keyboard guards](../src/lib/components/learning/keyboard.ts). Focused controls retain native activation. Escape pauses or opens exit confirmation without immediately discarding the session. Guard composition and held keys; displayed shortcuts must work.
- Expose session progress with accessible current/maximum values and announce prompt feedback through a live region.
- Exit dialogs need initial focus, contained Tab navigation, Escape/cancel behavior, and focus restoration. Background audio/hotkeys must not bypass a modal.
- Distinguish loading, empty history, initialization failure, audio failure, and unsaved progress. Only offer resume, replay, targeted review, or sync when the associated action is implemented.
- Verify newcomer/returning/review/complete states and full session intent/recovery paths in the browser. Inspect 320px, 390px, and desktop widths, both themes, translated wrapping, disclosure navigation, and overflow. Source review and a static build do not prove these interactions.

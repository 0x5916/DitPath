# Frontend UI/UX backlog

Reviewed against the current source on 6 October 2026. Findings below are source-confirmed implementation gaps or explicit acceptance requirements; browser reproduction and remediation verification remain required. This is a frontend design/correctness backlog, not a security audit.

## Implemented baseline

The Learn dashboard now has one page-padding owner, localized heading/path/status/disclosure/practice copy, nearby course rows with expandable earlier/later lessons, and a width-constrained recommendation skeleton. New-device guidance uses the existing 60-day attempt query, not lifetime history. Recommendation/session/practice/progress localization is still incomplete.

Home welcomes beginners with a direct Lesson 1 action and a curriculum-derived K/M listening area. The actions and device-local progress reassurance precede the sounds on mobile; desktop places them beside it. All five locales offer a separate free-practice link for experienced users. Large letter controls play sounds on request, mark completed listening, and offer replay. After both samples finish, an optional two-choice quiz gives encouraging feedback and a lesson action. The introduction and quiz show no Morse notation. Destination rows have icons and explicit link affordances. The desktop header begins at 800px with 44px control targets and a named landmark.

Progress and progression share batch mastery indexing; Learn preserves incremental reduction and its early exit. Learn now explains unmet character requirements, and session unlocks enforce the same introduced-character speed threshold. Only the latest unfinished session offers an explicitly labeled restart; restart and dismissal persist abandonment without removing saved answers. Exact saved-session restoration and guided server sync remain pending.

Guided feedback now uses the attempt's correctness independently of speed classification, including unmeasured warm-up answers. Expected and comparison sounds use controller-owned feedback playback without recording another attempt. Typing hints describe automatic submission, incomplete groups remain editable, and keyboard handlers guard composition, held keys, modifiers, and native activation. Misleading grid number hints were removed. A full 15-prompt lesson, both comparison sounds, pause/resume, and a fresh same-lesson retry were verified in the browser on 7 October 2026.

## Remaining packets

### Homepage optimization plan

The [homepage](../src/routes/+page.svelte) puts the lesson action and device-local reassurance below a conversational introduction, with an open listening area alongside on desktop and below on mobile. Lesson actions open the first guided session directly; the Learn navigation still opens the progress-aware dashboard. Sound buttons acknowledge natural playback completion and offer replay; an optional two-choice quiz becomes available after both samples finish. The UI uses no sound-decoding patterns or animations.

Acceptance for this packet: the lesson action and one-tap sound controls are visible at 375×667 and 1440×900; text/control contrast passes in both themes; all five locales fit; keyboard focus and activation work; playback stops on hide, navigation, and unmount. Use existing [color and focus tokens](../src/app.css) and the [audio engine](../src/lib/audio/engine.ts). Browser checks and the required frontend gates must pass before marking this packet complete.

Later packets remain separate:

- **P0:** simplify [desktop navigation](../src/routes/+layout.svelte), including the guest/theme/language controls and secondary destinations.
- **P1:** add a curriculum-based roadmap and review mobile navigation icons and safe-area behavior.
- **P2:** design measurement for first-listen time/rate, learning CTA conversion, Lesson 1 completion, and device-specific bounce. No existing analytics hook/provider was found; a new dependency or backend API requires approval.
- **P2:** verify first-tap audio on iOS and recovery guidance; validate [offline caching](../src/service-worker.ts), PWA discovery/installability, performance, screen-reader behavior, and Lighthouse accessibility on real devices. These are future acceptance work, not verified claims.
